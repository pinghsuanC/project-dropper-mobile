# 1060: Home

Accepted, Parts 1 (UI and redirection) and 2 (behaviour and calls) implemented · 2026-11-16 · Part of [1000 App](1000-app.md)

The screen after Landing's Welcome and after Register (`/home`, in the `(taskbar)` group).
Components are in [2010](2010-components.md); GIF slots in [2040](2040-gifs.md).

## Layout (top to bottom, scrolls on short screens)

1. **Balloon**: greeting, "QUOTE OF THE DAY", the session's quote (italic).
2. **Two GIFs** side by side: `homeLeft`, `homeRight` (half size).
3. **Main window**: date line ("Friday, Nov 13"), `homeMain` GIF (small), a large button with
   an icon, and a status line in some looks.
4. **Upload window** (ConfirmWindow), in the connected looks only.
5. **Taskbar** with Properties, from the `(taskbar)` layout, in **every** look.

**Two layout lessons (found on the emulator, 2026-11-16):**
- The big button is **stretched across the window body** (`alignItems: 'stretch'`, inset by
  `sizes.homeActionInset`), not sized by its label. Sized by content, with the icon above
  the label, Android measured the label as nearly zero wide: the button grew to about 2,400
  px (one letter per line) while the label drew on one line in its middle. Jest can't
  reproduce Android's text measuring, so a test pins the stretch instead.
- The `(taskbar)` layout's own Stack needs `contentStyle` with the desktop colour too;
  otherwise its screens show the platform's light grey.

## Greeting and date

- "Good morning" before 12:00, "Good afternoon" before 18:00, else "Good evening", then
  the user name, or **"friend"** when none is stored (`lib/greeting.ts`, pure functions of
  the time).
- Date: weekday, short month, day, in `DATE_LOCALE` (`config.ts`).
- They stay current while Home is open: `lib/useNow.ts` re-reads the clock every
  `CLOCK_TICK_MS` (`config.ts`, one minute), as the prototype's `tick()` did.

## Quote of the day

`lib/quotes.ts` `quoteForDate(date)`: one quote from `assets/quotes.json` per local calendar
day, in list order, wrapping around. Home puts it in the session (`setQuote`) when it opens
and when the day changes. No server route.

## The four looks

| Look | When | Window title | Button (icon) → | Status | Upload window |
|---|---|---|---|---|---|
| Checking | while the check runs, or `?state=checking` | Connected to your server | Checking… (globe), disabled | "Checking…" (muted) | yes |
| Not connected | check: no paired PC, or `?state=unpaired` | Not connected to a PC | I want to connect to my PC (monitor) → `/pairing/scan` | — | no |
| Connected | check: a paired PC, or `?state=paired` | Connected to your server | View server files (globe) → `/server-files` | "Server connected" (success) | yes |
| Can't reach | check failed, or `?state=serverError` | Can't reach your server | Retry (retry) → runs the check again on Home | "Server error, please check your server and retry." (error) | yes |

- A testing-menu state wins and skips the check; prod builds ignore states.

## The connection check

`lib/homeCheck.ts` `checkConnection()`, run when Home opens and by Retry. It never throws:

1. `GET /auth/me`: the session is still valid and the server answers.
2. `GET /devices/paired` (`getPairedDevice()` in `api/devices.ts`): a device goes into the
   session's `pairedWith` → **Connected**; `device: null` → `pairedWith` null →
   **Not connected**.
3. Any failure (unreachable, 5xx, 401, 403) → **Can't reach**. Logging in again after a
   401 (session older than 24 h) is left for later.

**Checking stays on screen (2026-11-18).** On a fast network the Checking look flashed by
and the window seemed to jump. Home waits for the check through `lib/wait.ts`
`atLeast(checkConnection(), MIN_CHECKING_MS)` (`config.ts`, 800 ms), both when it opens and
on Retry: the result shows no sooner than that, and a slower check isn't held any longer. A
testing-menu state still shows its look at once. The wait is not in `checkConnection()`,
which stays a plain check: it's in `lib/useConnection.ts` (`useConnection`, Retry is its
`recheck`), the hook Upload and Server status use for their status bars too.

**From a fake to the real route (2026-11-16).** Part 2 first returned a hard-coded PC from
the same function while the server route was 🚧. The route shipped the same day, returning
**one** device or `null` (not the list `API.md` first planned), so the function became
`getPairedDevice()` and the fake was removed; Home didn't change.

## Upload window

"Upload" · "Do you want to upload?" · **Yes** → `/upload` · **No** disabled. It **can't be
closed**: all its title-bar buttons are disabled (decided 2026-11-16).

## Taskbar

Shown on Home in every look, unpaired too (decided 2026-11-16; the prototype hid it on
unpaired Home), so Properties, which has its own "not paired" state, stays reachable. Also on
Server files and Upload. Properties → `router.push('/properties')`.
