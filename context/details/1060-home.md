# 1060: Home

Accepted, Part 1 implemented (UI and redirection) · 2026-11-16 · Part of [1000 App](1000-app.md)

The screen after Landing's Welcome and after Register (`/home`, in the `(taskbar)` group).
Components are in [2010](2010-components.md); GIF slots in [2040](2040-gifs.md).

## Layout (top to bottom, scrolls on short screens)

1. **Balloon**: greeting, "QUOTE OF THE DAY", the session's quote (italic).
2. **Two GIFs** side by side: `homeLeft`, `homeRight` (half size).
3. **Main window**: date line ("Friday, Nov 13"), `homeMain` GIF (small), a large button with
   an icon, and a status line in some looks.
4. **Upload window** (ConfirmWindow), in the connected looks only.
5. **Taskbar** with Properties, from the `(taskbar)` layout, in **every** look.

**Two layout lessons (found on the emulator, 2026-11-16):**
- The big button is **stretched across the window body** (`alignItems: 'stretch'`, inset by
  `sizes.homeActionInset`), not sized by its label. Sized by content, with the icon above
  the label, Android measured the label as nearly zero wide: the button grew to about 2,400
  px (one letter per line) while the label drew on one line in its middle. Jest can't
  reproduce Android's text measuring, so a test pins the stretch instead.
- The `(taskbar)` layout's own Stack needs `contentStyle` with the desktop colour too;
  otherwise its screens show the platform's light grey.

## Greeting and date

- "Good morning" before 12:00, "Good afternoon" before 18:00, else "Good evening", then
  the user name, or **"friend"** when none is stored (`lib/greeting.ts`, pure functions of
  the time).
- Date: weekday, short month, day, in `DATE_LOCALE` (`config.ts`).
- Part 1 computes both when Home renders; keeping them current while it stays open is Part 2.

## The three looks

| Look | When | Window title | Button (icon) → | Status | Upload window |
|---|---|---|---|---|---|
| Not connected | `pairedWith` null, or `?state=unpaired` | Not connected to a PC | I want to connect to my PC (monitor) → `/pairing/scan` | — | no |
| Connected | `pairedWith` set, or `?state=paired` | Connected to your server | View server files (globe) → `/server-files` | "Server connected" (success) | yes |
| Can't reach | `?state=serverError` | Can't reach your server | Retry (retry) → `/home` (Part 1) | "Server error, please check your server and retry." (error) | yes |

- A testing-menu state wins over the session; prod builds ignore states.
- **"Checking…" checks whether this phone is paired with a PC** (decided 2026-11-16), not
  the server. The pairing routes (`GET /devices/paired`) are 🚧 on the server, so the real app
  always shows **Not connected** for now; the other looks come from the testing menu.

## Upload window

"Upload" · "Do you want to upload?" · **Yes** → `/upload` · **No** disabled. It **can't be
closed**: all its title-bar buttons are disabled (decided 2026-11-16).

## Taskbar

Shown on Home in every look, unpaired too (decided 2026-11-16; the prototype hid it on
unpaired Home), so Properties, which has its own "not paired" state, stays reachable. Also on
Server files and Upload. Properties → `router.push('/properties')`.
