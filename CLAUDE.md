# File Dropper — Mobile App

@AGENTS.md

Keep the `@AGENTS.md` import above: it pulls in Expo's own guidance (generated by Expo).

Expo (React Native, TypeScript) app that sends files from this phone to my paired desktop
through my own FastAPI server. Server + desktop client live in a separate repo
(`file-dropper`); this repo is only the phone app.

## How the app works

1. **Device identity**: on first launch, generate an Ed25519 key pair. The private key is stored
   ONLY in `expo-secure-store`. Device fingerprint = SHA-256 hex of the Android ID (`expo-application`).
2. **Register**: `POST /auth/register` → save `device_id` in secure storage.
3. **Login**: `POST /auth/challenge` → sign → `POST /auth/verify_challenge` → session token (kept in memory).
   If `/auth/challenge` returns 404, the server forgot this device: re-register ONCE, then retry.
4. **Pairing** (M7): scan the desktop's QR (pairing code + server URL) → claim it on the server.
5. **Send a file**: pick file → `POST /files/prepare-upload` → PUT bytes to `upload_url` → `POST /files/finish-upload`.

## Server API contract (must match exactly)

All responses use the envelope `{ "message": string, "data": ... }`. Errors are `{ "detail": ... }`.
Protected routes need `Authorization: Bearer <session_token>`.

| Route | Body | Returns `data` |
|---|---|---|
| `POST /auth/register` | `name, platform ("android"), public_key, fingerprint` | `{ device_id }` (409 = key already registered) |
| `POST /auth/challenge` | `device_id` | `{ challenge }` (404 = unknown device) |
| `POST /auth/verify_challenge` | `device_id, challenge, signature` | `{ token }` (401 = invalid) |
| `GET /auth/me` | — | `{ device_id, name, platform }` |
| `POST /files/prepare-upload` | `file_name, size, content_type, checksum, receiver_id` | `{ file_id, upload_url }` |
| `POST /files/finish-upload` | `file_id` | `{ file_id }` (409 = upload missing/incomplete) |

Field names are snake_case and must match the server's Pydantic models — a mismatch is a 422.
Check the server's `/docs` page when unsure; do not guess field names.

## Crypto rules (do not change without asking)

- `public_key` must be a **PEM, SubjectPublicKeyInfo** encoding of the raw 32-byte Ed25519 key
  (`-----BEGIN PUBLIC KEY-----`). The server rejects anything else with 400.
- Sign **exactly** the challenge string as UTF-8 bytes. Do NOT base64-decode it before signing.
- Signature is sent base64-encoded.
- `checksum` = lowercase hex SHA-256 of the file's bytes (64 chars).
- Never log, print, or display: the private key, session tokens, presigned URLs.
- The private key never leaves secure storage except to sign, and is never sent anywhere.

## UI style: Windows 98 inspired

- **Hard rules:** `StyleSheet` + `theme.ts` only. No Tailwind / NativeWind, no UI component
  libraries. "Inspired by" only: no Microsoft logos, fonts, or sounds.
- **Find the details first.** Before any UI work, read `context/details/2000-ui.md` and the
  record for what you're touching (2010 components, 2020 text, 2030 colours, 2040 GIFs).
  They're the source of truth; this file doesn't repeat them.
- **Reuse before creating.** Look in `src/components/ui/` and 2010-components for a
  component that does the job, or would with one more prop. Prefer extending over creating.
- **If unsure, ask.** If it's unclear whether to reuse, extend or create, or the records
  don't cover the case, stop and ask the user, with the options in a line or two each.
- **Write it back.** Once a new component, prop or style is agreed, add it to the right
  layer folder and to its record (2010–2040).
- No hex colours, font sizes or spacing values in components or screens: only `theme.ts`
  tokens.

## Code conventions

- All source lives in `src/` and is imported through the `@/` alias (`@/components/ui`).
  Folder names in this file (`api/`, `lib/`, `components/`) are under `src/`.
- Routes only in `src/app/` (Expo Router: every file there is a screen). Everything else
  goes outside it.
- TypeScript strict. No `any` in API types — define them in `api/types.ts`.
- All server calls go through `api/client.ts` (adds the auth header, unwraps the envelope,
  throws `ApiError(status, detail)` on non-2xx). Screens never call `fetch` directly.
- Keep crypto in `lib/crypto.ts` and storage in `lib/storage.ts` so they can be unit tested.

## Constants and text

- Config values (API paths, timeouts, size limits, retry counts, storage keys) go in
  `src/constants/config.ts`. It's also the only file that reads `process.env`.
- All user-facing text goes in `src/constants/strings.ts`, grouped by screen, for later
  translation. Text with values in it is a function, e.g. `sent: (fileName) => ...`, never
  joined from pieces.
- Colors, spacing and font sizes go in `theme.ts`, not `src/constants/`.
- Only `EXPO_PUBLIC_*` variables reach the app, and they're readable by anyone with the
  APK. Never put a secret in one.

## Testing

- Write tests before the feature code, from the requirements, and see each fail on its
  assertion before implementing.
- Jest with the `jest-expo` preset, `@testing-library/react-native` for components.
  Test files end in `-test.ts(x)` or `.test.ts(x)`. `render` is async: `await render(...)`.
- Unit test the logic first: PEM wrapping, sign/verify round trip, checksum, API client error handling.
- Mock `expo-secure-store` and `fetch`; tests never hit the real server or R2.
